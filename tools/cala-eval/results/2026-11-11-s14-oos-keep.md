Base = E6 runs, seeds 5-9, `--batch 8 --budget 30000000 --slow-seed 1`. `oos` = this branch with `--holdout-folds 2`:
a footprint records the fold it was estimated from (`Cell::fit_folds`), and a keep-test probe from that fold tests the
footprint re-estimated from the other fold's running statistics (one-sided when the other fold has no estimate yet).
`folds2` = the previous commit (keep tests on the published footprint), from `2026-11-11-s14-rotating-folds.md`.

## Reading

The fix removes a real leak and moves P8 up by about .005 to .009 against `folds2` on every arm, at 1x and 4x, at no
recall cost (R8 is slightly up). It does not close the compute-vs-precision gap: -0.049 against the base -0.045. Keep
tests on in-sample probes were not what drove the gap.

The fixed split's gap is not explained by cleaner tests alone. At 4x it holds 96 fewer cells than base, with fp_noise
-11, fp_adjacent -14, fp_dup -9 and R8 -.09. It has less held-out data per test and never fits a third of the frames,
which puts it at a lower-power operating point.

Leak paths that remain with two folds, for S2.1:

- **Probe selection.** A probe is chosen because the fast-loop trace was high on that frame. That trace is the
  projection of the frame onto the footprint, so a footprint that fits noise selects frames where noise lines up with
  it. The fold change does not affect this, and the fixed split has it too.
- **Repeated looks across folds.** A rejected candidate comes back at the next visit, fitted on the other fold and
  tested on a fresh fold. With a fixed split, retests reuse the same held-out frames, so their outcomes are correlated.
  This is the `m(n_looks)` question in S2.1.
- **Evidence ledger.** Establishment events come from the fast-loop trace on all frames, which is in-sample for both
  folds.
- **Status-quo bias.** Refine, merge, split and add tests compare against base columns that may have been fitted on the
  tested fold. This bias works against edits, not towards false positives.

R2 remains -.09 to -.10 on every arm, the same as `folds2`. It is likely the blocked split delaying the first tests
(three held-out blocks, not tested here), not the keep tests.

Recommendation: keep `holdout_folds = 1` as the default. The out-of-sample keep test is correct and costs nothing when
`holdout_folds = 1`, so it stays in the code for `holdout_folds = 2`.
