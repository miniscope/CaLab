# S2.1c F0: shadow of the evidence rules on ctl (main 7d4569c)

12 Nov 2026. PR 0 of `S2.1c-plan.md`: `discover/decide.rs` and the shadow log (`qc_eval --decide-shadow`,
`--features diagnostics`), no decision changed. **Verdict: F0 fails; do not start PR 1.** The new statistic ranks
refines better than the paired z, but the energy-weighted Δ test almost never passes: a cell's held-out energy sits in
one or two 256-frame blocks, so `G_eff − 1` is about 1 and the Student-t tail is too heavy for any margin. Early
footprints would be frozen (1 % power, stop rule < 20 %). The late real cut (0 %) comes from that same freeze, not from
the margin: with the dof ignored the rule would publish as many late refines as today (102 %, stop rule > 50 %).

## Runs

- `ctl` = origin/main 7d4569c (BasinSkirt default since #358; `--support-rule basin-skirt` also passed), built with
  `--features diagnostics`, `--decide-shadow`, `α₀ = 1e-3`.
- Sims: `$CALA_SIMS` (sims-gt110), `static` and `motion`, seeds 5–9, `--batch 8 --budget 30000000 --slow-seed 1
--churn-log` (+ `--motion` on motion). Real: the workshop recording, `real … --motion --frames 18000 --batch 8
--budget 30000000 --via-jobs --churn-log --slow-seed {1,2}`. Scored with `tools/cala-eval/decide_f0.py`.
- Wall time and RSS unchanged within noise (motion s5: 310 s with the shadow vs 324 s base; RSS ≤ 1.4 GB on every run).

Why nothing passes (pooled refine rows): energy-weighted dof quartiles 0.35 / 0.94 / 1.6 on sims, 0.46 / 1.14 / 2.1
on real; 44–53 % of tests have dof < 1 and cannot pass by construction. Test frames span 7–14 blocks, but the weight
`c²q` sits in the event slots of one or two transients. The frame-weighted fallback has dof ≈ 4 but its standard error
is dominated by the same few event blocks (median p ≈ .16): 0 % power. The look margin is not the obstacle: at the
median 4 looks the margin is 4.9, and 80 % of the improving early refines have t above it.

The other shadow rules:

- **Merge** (section 1.3a): 3 shadow merges among 489 sim current-rule merges (all three also merged by it), 0 among 549 real. A true duplicate's
  arm has θ ≈ 0 (the second column buys about what a noise column buys), and "θ significantly below 0" is then the
  null itself, so it cannot pass. The plan's claim that a duplicate "still merges on its first or second look" does
  not hold; the merge question needs an equivalence-type test or an effect size (D2's alternative), not θ < 0.
  The dropped-cell arms carry θ of 10–1000 per frame (dropping a real cell), so "confirm apart" (all three arms
  > 0) never passed either, because the merged arm sits near 0.
- **Keep** (1.3b): θ (share of claimed light surviving a free local background) does not separate TP from non-TP
  cells (AUC .46–.68); 1–2 shadow deletions per run, 0–1 of them matching a current Unsupported deletion (8–14
  per sim run). About 1 probe per visit, so records grow 1 block per visit; at the ½ boundary nothing confirms.
- **Silent** (1.3c): claims at the add are mostly one block (`k = 1`, `λ = 1/256`, wait 1768 frames), shorter than
  today's 4800-frame probation. The shadow would delete 11–22 cells per sim run, 145 of 176 of them TP-matched, and
  63–79 per real run (current rule: 0–1 sim, 10–12 real). D3's derived wait is too short when the claim is a single
  block.

## What the plan got wrong against the code

- **Energy weights collapse `G_eff`** (1.2): the plan expected sparse firing to cost only variance; with `w = c²q` it
  costs the degrees of freedom, and the Student-t tail with dof ≈ 1 makes the test unpassable. Any PR 1 needs a different
  unit of independence (frames within an event block are not independent, but blocks without the cell's energy do not
  add information either), or a test whose reference distribution does not depend on `G_eff`.
- **Merge θ < 0** (1.3a): see above; duplicates sit on the null.
- **Units of the trigger** (1.2): `Î` and `D²` built on the estimate's scale need dividing by the fit scale `a²` before
  `z_pred` uses the cell's trace `c` (which multiplies the current column). The shadow logs them in current-column
  units.
- **Absorb / even–odd blocks**: early in a run every test frame is in block 0, so the odd-block confirmation has no
  data for the first 256 frames (absorbs are frequent then).
- Plan section 0 is otherwise accurate against main 7d4569c. `TestEvent` was not extended: the shadow writes its own
  files (`decide_*.tsv`) so `tests.tsv` stays byte-identical. Keep decisions are made in `keep_tests` (where the
  probes are solved, also inside jobs), not in `prune`; tomb inheritance of keep evidence and `looks_spot` / the add
  shadow were not implemented (not needed for F0). In `--via-jobs` runs the keep rows' pass/fail/transient display
  columns are 0 (the job carries only ledger ids).
